# Core 0.3 Runtime Contract Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver Core `0.3.0` through `0.3.2`: freeze `frontend-contract-v1`, move authoritative lane execution into Core, and complete a replayable local evidence-to-merge loop for TUI and GUI clients.

**Architecture:** `viden-types` owns the versioned wire/domain schema; `viden-session` and `viden-workflows` own append-only facts and rebuildable indexes; `viden-tools` owns local effects; `viden-runtime` owns routing, supervision, permissions, reduction, and recovery; `viden-core` exposes the only frontend client boundary. Existing unversioned records remain readable through explicit v0 migration, while new clients negotiate schema and capabilities before sending commands.

**Tech Stack:** Rust 2024, serde/serde_json, JSONL canonical logs, rebuildable SQLite indexes, std channels/threads, existing Viden provider/permission/tool/runtime crates.

## Global Constraints

- Work only on `codex/v3-core-runtime` in `.worktrees/v3-core-runtime`, created from synchronized `origin/main` after this plan/spec lands.
- Core owns `crates/**`; do not add dependencies on `apps/tui` or `apps/gui`.
- Publish one immutable `frontend-contract-v1` checkpoint after Task 7; record its exact SHA and never rewrite it after frontend branches start.
- Preserve append-only JSONL as canonical; SQLite remains derived and rebuildable.
- Permission and Plan-mode checks must complete before file, shell, Git, workflow, memory, task, lane, apply, or cleanup mutation.
- Built-in roles are `planner`, `coder`, `reviewer`, `tester`, `doc-writer`, `researcher`, and `release-operator`; external is a route/source capability, not a role.
- Core facts use stable message keys/error codes plus arguments. They do not contain frontend-localized sentences that clients must parse.
- UI preference precedence is CLI override -> user preferences -> project-safe defaults -> client capability defaults. Project config cannot force personal locale/theme/density/motion.
- Core `0.3.0` freezes wire schema `1`; Core `0.3.1` and `0.3.2` extend schema `1` compatibly.
- Every behavior task follows red -> green -> focused tests -> commit. Update English and Chinese docs together.

```rust
pub trait CoreTransport: Send {
    fn discover(&mut self) -> Result<CoreHandshake, CoreClientError>;
    fn send(&mut self, command: RuntimeCommandEnvelope) -> Result<(), CoreClientError>;
    fn recv(&mut self, timeout: Duration) -> Result<Option<RuntimeEventEnvelope>, CoreClientError>;
    fn snapshot(&mut self) -> Result<RuntimeSnapshotEnvelope, CoreClientError>;
    fn replay(&mut self, request: ReplayRequest) -> Result<ReplayBatch, CoreClientError>;
    fn transcript_page(&mut self, request: TranscriptPageRequest) -> Result<TranscriptPage, CoreClientError>;
}
pub trait CoreClient: Send {
    fn discover(&mut self) -> Result<CoreHandshake, CoreClientError>;
    fn send(&mut self, command: RuntimeCommandEnvelope) -> Result<(), CoreClientError>;
    fn recv(&mut self, timeout: Duration) -> Result<Option<RuntimeEventEnvelope>, CoreClientError>;
    fn snapshot(&mut self) -> Result<RuntimeSnapshotEnvelope, CoreClientError>;
    fn replay(&mut self, request: ReplayRequest) -> Result<ReplayBatch, CoreClientError>;
    fn transcript_page(&mut self, request: TranscriptPageRequest) -> Result<TranscriptPage, CoreClientError>;
}
pub struct StatefulCoreClient<T: CoreTransport> { transport: T, handshake: CoreHandshake, view: RuntimeViewState, cursor: EventCursor, recovering: bool }
```

`StatefulCoreClient<T>` implements the object-safe `CoreClient` trait and owns gap recovery, so TUI/GUI can hold `Box<dyn CoreClient>` without knowing the transport. `RuntimeEventJournal` uses a bounded `VecDeque` (default 10,000), a stable stream id per runtime lifetime, and returns `SnapshotRequired` when a cursor is from another stream or precedes retained history. `CoreClient` must not expose `SessionEngine`.

**Implementation notes (as delivered):**

- `AuditAction` is not a separate type. The stable dotted message key is
  `AuditRecord::action`, validated by `AuditRecord::sanitized` to reject
  capitals, spaces, and any other prose shape.
- Emission lives in `crates/runtime/src/trust_loop.rs` and the read command in
  `crates/runtime/src/runtime_contract.rs` plus
  `crates/runtime/src/frontend_services.rs`;
  `crates/runtime/src/session_lifecycle.rs` needed no change.
- Audited actions: `handoff.created`, `review.requested`, `contract.confirmed`,
  `dependency.set`, `gate.decided` (the permission-gated accept/reject),
  `evidence.rejected`, `conflict.bounced`, `conflict.revalidated`, and
  `change.reverted`. Each reuses the audit id already stored on its trust
  record. A failed audit append fails the trust action (fail-closed), and every
  site appends before it mutates.
- Scope rule: operator decisions and revalidation are audited; the automatic
  `AwaitingEvidence` gate re-stamps written during evidence collection are
  bookkeeping, not operator actions, and are deliberately not audited.
- `change.reverted` is appended before `stage_rollback_paths` /
  `restore_file_rollbacks`. If restoration then fails, the orphaned audit
  record is detectable evidence of the attempt; the reverse order would leave
  reverted bytes with no audit fact at all.
- SQLite remains uninvolved: queries scan `audit.jsonl`, and a malformed line
  is a hard error rather than a skipped record.
