# Viden TUI 0.2 薄客户端实施计划

> **面向 agentic workers：** 必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans`，逐任务实施本计划。步骤统一使用 checkbox（`- [ ]`）追踪。

英文版：[2026-07-19-tui-0.2-thin-client.md](2026-07-19-tui-0.2-thin-client.md)

**目标：** 交付 TUI `0.2.0-alpha.1`、`0.2.0` 和 `0.2.1`：它只能通过 CoreClient 工作，落实已接受的 welcome 到 cockpit 主路径、稳定三态交互、本地监督闭环、多语言和 token 派生的外观配置。

**架构：** 不可变 `frontend-contract-v1` Core checkpoint 是硬启动门。TUI 只保存一份由 Core 提供的规范 `RuntimeViewState`，另用 `TuiUiState` 保存焦点、选择、浮层、composer 草稿、滚动偏移和 UI 偏好。`app.rs` 收缩为 crossterm 与 `CoreClient` 之间的事件泵；渲染模块只投影结构化 Core 事实，不扫描工作区、不解析 transcript 文案，也不执行 runtime、Git、worktree、PTY、tmux、permission、provider 或 Lane 权威副作用。

**技术栈：** Rust 2024、`viden-core` 前端合同、`viden-types` command/event/view 类型、crossterm 0.28、`unicode-segmentation`、`unicode-width`、JSON locale catalog、从 `docs/viden-design/Viden/tokens.css` 生成的 Rust palette。

## 全局约束

- 只有 `git rev-parse refs/tags/frontend-contract-v1^{commit}` 成功后，才能从该精确 commit 创建 `.worktrees/v3-tui-client` 和 `codex/v3-tui-client`。
- 生产写范围限于 `apps/tui/**`、TUI 专属证据脚本/产物以及成对的中英文 TUI 文档。合同缺口回到 Core。
- TUI 只经 CoreClient 发送 `RuntimeCommand`、消费有序 `RuntimeEvent`、渲染 `RuntimeViewState`；不得自行构造权威成功。
- TUI 本地状态只允许布局、焦点、选择、过滤、排序、展开、composer 草稿、scrollback、终端能力和 UI 偏好。
- 保留 `0.1.30` zero-bug 基线：streaming、tool、approval 期间 composer 始终可编辑；queue、cancel、scrollback、resize、focus、CJK 和 selector 不得回归。
- 视觉审查顺序为全局 index -> TUI 设计稿索引 -> TUI 组件库 -> `TUI/Viden - 统一原型 (TUI).html`；`tokens.css` 是数值 token 真源。
- 内置 locale 为 `en` 与 `zh-CN`。fallback 为请求 locale -> 同语言默认变体 -> `en` -> 可见 key。
- 外观支持五种 skin（`aurora`、`ice`、`mono`、`amber`、`phosphor`）、八种有效 skin/mode、三种 density、三种 motion 策略，以及 TUI `auto | truecolor | ansi256 | ansi16` 色深。
- `amber`、`phosphor` 只支持 dark。无效组合或不完整 palette 必须整套回退 Aurora dark/regular，并显示一次非阻塞诊断。
- 默认关闭 mouse capture。所有动作必须有键盘路径；只用登记 glyph，不新增 emoji。
- 每个行为任务都按 RED -> GREEN -> REFACTOR，并以 focused commit 收尾。改变行为的任务同步更新双语文档和必要的不变量注释。

## 本计划要求的 Core Checkpoint 合同

不得在 `apps/tui` 内模拟缺失能力。checkpoint 必须从 `viden_core` 导出以下精确名字：

```rust
pub trait CoreClient: Send {
    fn discover(&mut self) -> Result<CoreHandshake, CoreClientError>;
    fn send(&mut self, command: RuntimeCommandEnvelope) -> Result<(), CoreClientError>;
    fn recv(&mut self, timeout: Duration) -> Result<Option<RuntimeEventEnvelope>, CoreClientError>;
    fn snapshot(&mut self) -> Result<RuntimeSnapshotEnvelope, CoreClientError>;
    fn replay(&mut self, request: ReplayRequest) -> Result<ReplayBatch, CoreClientError>;
    fn transcript_page(&mut self, request: TranscriptPageRequest) -> Result<TranscriptPage, CoreClientError>;
}
```

envelope 必须包含 schema version、stream/session identity、sequence/cursor 和 capabilities。`RuntimeViewState::apply_event` 仍是唯一业务 reducer。Core 还必须拥有下文所需的 typed project setup、lane/session lifecycle、owner-scoped cancel、approval choices、evidence、MergeGate、apply/recovery、transcript paging 和 preference persistence command/fact。TUI driver 可以在 `CoreClient` 上增加服务于帧调度的 `pump`/`poll` adapter，但不得另定义一套 transport/client trait。

如果冻结 checkpoint 使用了不同名字，Core owner 必须在 Task 1 开始前同步更新本计划及英文对应文件。不得在 TUI 增加第二套 wire protocol。
