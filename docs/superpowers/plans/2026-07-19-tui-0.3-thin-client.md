# Viden TUI 0.3 Thin Client Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

Chinese version: [2026-07-19-tui-0.3-thin-client.zh-CN.md](2026-07-19-tui-0.3-thin-client.zh-CN.md)

**Goal:** Deliver TUI `0.3.0-alpha.1`, `0.3.0`, and `0.3.1` as a CoreClient-only terminal client with the accepted welcome-to-cockpit flow, stable modal input grammar, local supervision loop, localization, and token-derived appearance preferences.

**Architecture:** The immutable `frontend-contract-v1` Core checkpoint is a hard start gate. The TUI stores one canonical `RuntimeViewState` supplied by Core and a separate `TuiUiState` containing only focus, selection, overlays, composer draft, scroll offsets, and UI preferences. `app.rs` becomes an event pump between crossterm and `CoreClient`; render modules project structured Core facts and never scan the workspace, parse transcript prose, or execute runtime, Git, worktree, PTY, tmux, permission, provider, or lane effects.

**Tech Stack:** Rust 2024, `viden-core` frontend contract, `viden-types` command/event/view types, crossterm 0.28, `unicode-segmentation`, `unicode-width`, JSON locale catalogs, generated Rust palettes from `docs/viden-design/Viden/tokens.css`.

## Global Constraints

- Do not create `.worktrees/v3-tui-client` until `git rev-parse refs/tags/frontend-contract-v1^{commit}` succeeds; create `codex/v3-tui-client` from that exact commit.
- Production writes are limited to `apps/tui/**`, TUI-specific evidence scripts/artifacts, and paired English/Chinese TUI documentation. Contract gaps go back to Core.
- TUI sends `RuntimeCommand` only through CoreClient, consumes ordered `RuntimeEvent`, and renders `RuntimeViewState`; it never constructs authoritative success.
- TUI-local state is limited to layout, focus, selection, filters, sorting, expansion, composer draft, scrollback, terminal capabilities, and UI preferences.
- Preserve the `0.1.30` zero-bug baseline: composer remains editable during streaming, tools, and approvals; queue, cancel, scrollback, resize, focus, CJK, and selectors must not regress.
- Accepted visual order is global index -> TUI design index -> TUI component library -> `TUI/Viden - 统一原型 (TUI).html`; `tokens.css` is the numeric token source.
- Built-in locales are `en` and `zh-CN`. Fallback is requested locale -> default variant -> `en` -> visible key.
- Supported appearance is five skins (`aurora`, `ice`, `mono`, `amber`, `phosphor`), eight valid skin/mode combinations, three densities, three motion policies, and TUI color depth `auto | truecolor | ansi256 | ansi16`.
- `amber` and `phosphor` are dark-only. An invalid or incomplete palette falls back atomically to Aurora dark/regular and emits one non-blocking diagnostic.
- Mouse capture is off by default. Every action has a keyboard path. Use the registered glyph set and add no emoji.
- Every behavior task follows RED -> GREEN -> REFACTOR and ends with a focused commit. Update paired docs and invariant comments in the task that changes the behavior.

## Core Checkpoint Contract Required by This Plan

Do not emulate missing items in `apps/tui`. The checkpoint must export these exact names from `viden_core`:

```rust
pub trait CoreClient: Send {
    fn discover(&mut self) -> Result<CoreHandshake, CoreClientError>;
    fn send(&mut self, command: RuntimeCommandEnvelope) -> Result<(), CoreClientError>;
    fn recv(&mut self, timeout: Duration) -> Result<Option<RuntimeEventEnvelope>, CoreClientError>;
    fn snapshot(&mut self) -> Result<RuntimeSnapshotEnvelope, CoreClientError>;
    fn replay(&mut self, request: ReplayRequest) -> Result<ReplayBatch, CoreClientError>;
    fn transcript_page(&mut self, request: TranscriptPageRequest) -> Result<TranscriptPage, CoreClientError>;
}
```

The envelope types must carry schema version, stream/session identity, sequence/cursor, and capabilities. `RuntimeViewState::apply_event` remains the sole business reducer. Core also owns typed project setup, lane/session lifecycle, owner-scoped cancel, approval choices, evidence, MergeGate, apply/recovery, transcript paging, and preference persistence commands/facts required below. The TUI driver may add a `pump`/`poll` adapter over `CoreClient` for frame scheduling, but it must not define another transport/client trait.

If the frozen checkpoint uses different names, the Core owner must update this plan and its Chinese counterpart before Task 1 starts. Do not add a second wire protocol in TUI.
