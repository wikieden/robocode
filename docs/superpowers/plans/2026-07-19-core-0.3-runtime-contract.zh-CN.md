# Core 0.3 Runtime Contract 实施计划

> **面向 agentic workers：** 必须使用子技能 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans`，按任务逐项实施。本计划使用复选框跟踪步骤。

**目标：** 交付 Core `0.3.0` 到 `0.3.2`：冻结 `frontend-contract-v1`，把权威 Lane 执行上收 Core，并为 TUI/GUI 提供可重放的本地 evidence-to-merge 闭环。

**架构：** `viden-types` 拥有版本化 wire/domain schema；`viden-session` 与 `viden-workflows` 拥有追加式事实和可重建索引；`viden-tools` 拥有本地副作用；`viden-runtime` 拥有路由、监督、权限、归约与恢复；`viden-core` 是前端唯一客户端边界。旧无版本记录通过明确的 v0 migration 继续可读，新客户端必须先协商 schema/capability 再发送命令。

**技术栈：** Rust 2024、serde/serde_json、JSONL canonical log、可重建 SQLite 索引、std channel/thread、现有 Viden provider/permission/tool/runtime crates。

## 全局约束

- 只在 `.worktrees/v3-core-runtime` 的 `codex/v3-core-runtime` 开发；它必须在本计划和规格进入同步后的 `origin/main` 之后创建。
- Core 拥有 `crates/**`；禁止依赖 `apps/tui` 或 `apps/gui`。
- Task 7 后发布唯一不可变 `frontend-contract-v1` checkpoint；前端分支开始后不得重写该 SHA。
- JSONL 始终是 canonical 事实；SQLite 始终是可删除、可重建的派生索引。
- file、shell、Git、workflow、memory、task、lane、apply、cleanup 的副作用前必须完成 permission 与 Plan-mode 检查。
- 内置角色固定为 `planner/coder/reviewer/tester/doc-writer/researcher/release-operator`；external 是 route/source capability，不是角色。
- Core 事实只发布稳定 message key/error code 和参数，不发布要求前端解析的本地化句子。
- UI 配置优先级为 CLI override -> user preferences -> project-safe defaults -> client capability defaults；项目不能强制个人 locale/theme/density/motion。
- Core `0.3.0` 冻结 wire schema `1`；`0.3.1`、`0.3.2` 只能兼容扩展 schema `1`。
- 每个行为任务执行红灯 -> 绿灯 -> focused tests -> commit；用户可见文档中英文同步。

```rust
pub trait CoreTransport: Send {
    fn discover(&mut self) -> Result<CoreHandshake, CoreClientError>;
    fn send(&mut self, command: RuntimeCommandEnvelope) -> Result<(), CoreClientError>;
    fn recv(&mut self, timeout: Duration) -> Result<Option<RuntimeEventEnvelope>, CoreClientError>;
    fn snapshot(&mut self) -> Result<RuntimeSnapshotEnvelope, CoreClientError>;
    fn replay(&mut self, request: ReplayRequest) -> Result<ReplayBatch, CoreClientError>;
    fn transcript_page(&mut self, request: TranscriptPageRequest) -> Result<TranscriptPage, CoreClientError>;
}
pub trait CoreClient: Send {
    fn discover(&mut self) -> Result<CoreHandshake, CoreClientError>;
    fn send(&mut self, command: RuntimeCommandEnvelope) -> Result<(), CoreClientError>;
    fn recv(&mut self, timeout: Duration) -> Result<Option<RuntimeEventEnvelope>, CoreClientError>;
    fn snapshot(&mut self) -> Result<RuntimeSnapshotEnvelope, CoreClientError>;
    fn replay(&mut self, request: ReplayRequest) -> Result<ReplayBatch, CoreClientError>;
    fn transcript_page(&mut self, request: TranscriptPageRequest) -> Result<TranscriptPage, CoreClientError>;
}
pub struct StatefulCoreClient<T: CoreTransport> { transport: T, handshake: CoreHandshake, view: RuntimeViewState, cursor: EventCursor, recovering: bool }
```

`StatefulCoreClient<T>` 实现 object-safe `CoreClient` trait 并拥有 gap recovery，因此 TUI/GUI 可持有 `Box<dyn CoreClient>` 而无需了解 transport。Journal 默认保留 10,000 events；跨 stream 或早于 retained history 必须 `SnapshotRequired`；CoreClient 不暴露 `SessionEngine`。

## 依赖与并行顺序

```text
Task 1 protocol
  -> Task 2 typed domain
  -> Task 3 approval
  -> Task 4 UI preference schema（Task 1 后可与 Task 3 并行）
  -> Task 5 transcript paging
  -> Task 6 journal/CoreClient
  -> Task 7 immutable frontend-contract-v1
  -> 前端分支可从 Task 7 的准确 SHA 启动

Task 8 effects 与 Task 9 lane persistence 可在 Task 7 后并行
  -> Task 10 multi-lane supervisor
  -> Task 11 onboarding（Task 7 后可与 Task 10 并行）
  -> Task 12 trust loop
  -> Task 13 audit timeline
  -> Task 14 full integration gate
```

`crates/types/**` 的共享 schema 同时只允许一个 implementation owner。Task 8 与 Task 9 写范围不重叠，可并行；两者进入 runtime 的集成必须串行。Task 7 后，TUI/GUI 从同一 checkpoint 并行；Core 后续只做 schema-1 向后兼容扩展。
