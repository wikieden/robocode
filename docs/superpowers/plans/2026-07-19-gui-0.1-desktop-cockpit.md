# Viden GUI 0.1 Desktop Cockpit Implementation Plan

Chinese version: [2026-07-19-gui-0.1-desktop-cockpit.zh-CN.md](2026-07-19-gui-0.1-desktop-cockpit.zh-CN.md)

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship GUI `0.1.0-alpha.1`, `0.1.0-beta.1`, and `0.1.0`: select Tauri or GPUI by evidence, then deliver D11 -> D4 -> D1 -> permission/D6 -> evidence/gate/apply/recovery as a bilingual, themeable, accessible local operator loop.

**Architecture:** GUI consumes the immutable `frontend-contract-v1` checkpoint through a transport-neutral `CoreClient`. `GuiCoreAdapter` applies ordered envelopes through Core's canonical `RuntimeViewState` and requests snapshot/replay on gaps. GUI owns presentation state only. Alpha keeps equal Tauri and GPUI slices in an isolated nested workspace; only the selected framework joins the root Cargo workspace.

**Tech Stack:** Rust 2024, `viden-core`, the framework selected by Task 4, built-in `en`/`zh-CN`, `tokens.css`/`gui-kit.css`, shared replay fixtures, framework-native interaction and screenshot tests.

## Global Constraints

- Create `codex/v3-gui-client` in `.worktrees/v3-gui-client` from the exact immutable Core checkpoint SHA. Do not guess the SHA or start production work before it exists.
- GUI owns `apps/gui/**`. Root `Cargo.toml`, shared fixtures, `.github/**`, and design-package files require serialization with their owners.
- GUI Rust code depends on `viden-core`, GUI-owned crates, and framework/platform libraries only; it must not depend on runtime/provider/tools/permissions/session/workflows/context/config crates.
- Every business mutation is a `RuntimeCommand`; visible success waits for ordered `RuntimeEvent` confirmation. A sequence gap enters recovery and blocks success until snapshot/replay completes.
- The alpha candidates replay the same D1 fixture and implement theme/density, composer/CJK IME, streaming/tool rows, approval, queue, cancel, history scroll, 10,000 events, and 50,000 transcript rows.
- Any GPUI failure in IME, accessibility, three-platform build/launch, bounded transcript rendering, or no-long-lived-fork makes GPUI a no-go and selects Tauri.
- Locales are `en` and `zh-CN`; fallback is requested locale -> language default -> `en` -> visible key. Do not translate code, paths, commands, or identifiers.
- Preferences are `skin=aurora|ice|mono|amber|phosphor`, `mode=dark|light|system`, `density=compact|regular|comfy`, and `motion=system|reduced|full`. Amber/Phosphor are dark-only; invalid combinations visibly fall back to Aurora dark/regular.
- `tokens.css` is the numeric visual source; `gui-kit.css` and `DESIGN-REF.md` define component semantics. No hand-copied colors or emoji; visible focus, reduced motion, and non-color status cues are gates.
- D1 visual source is `docs/viden-design/Viden/GUI/Viden - 桌面驾驶舱 (GUI).html`; D11, D4, and D6 use their files under `GUI/pages/`.
- Every release manifest records component version, minimum Core version, schema versions, Core SHA, capabilities, design revision, locale revision, and token revision.
- `apps/gui/release-manifest.toml` is the machine-readable active manifest; `apps/gui/manifests/<version>.toml` is the byte-equivalent immutable snapshot for each GUI release.
