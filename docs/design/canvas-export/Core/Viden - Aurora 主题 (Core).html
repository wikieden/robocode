Aurora — the visual theme for viden’s terminal cockpit

Skin only, no layout change. This theme organizes what the existing 0.1.30 TUI already has («deep blue-black ground + cyan borders + gold attention + green success») into a named, layered token system that degrades to ANSI 256, and establishes the selected highlight row as the visual anchor of the whole interface.

Primary cyan (same as the robot logo) Secondary gold (viden wordmark / work mode) Target truecolor · degrades to ANSI 256 Toggle Dark / Light top-right

What I read of the status quo

The original wordmark Robo gold / Code cyan carries into viden as v gold, iden cyan; the mascot robot head is a cyan line drawing. In the current UI cyan is border, title and highlight all at once — semantically «flat». Gold already carries three things: «tool gating / pending approval / work mode».

My call

Converge cyan to a single role: «brand + interaction focus». Deepen background depth into three tiers — main ground / panel / highlight row — making the selected highlight the brightest line. Gold is dedicated to the «needs a human» attention semantic; green/red/blue fill success / failure / in-progress.

Hard constraints I kept

Everything aligns to monospace cells; no sub-pixel / no rounded corners / no shadows (inside the TUI); borders use box-drawing only; CJK wide chars take two cells; every token has an ANSI 256 approximation, and at 256 colors the highlight row degrades to neutral gray but keeps the cyan left bar so focus is not lost.

Color tokens · hex + ANSI 256

Theme color system

Four token groups: background tiers, foreground tiers, accents, semantics. Each gives a hex (truecolor target) + ANSI 256 approximation (degraded) + Light-variant value. The tables below highlight the active value live with the top-right theme toggle.

① Background tiers

Opening three depth tiers is the core change: main ground deepest, panel raised one step, highlight row brightest. At 256 colors the highlight degrades to neutral gray, keeping focus via the cyan left bar.

TokenDark hexANSI 256Light hexUse

② Foreground tiers

Four text tiers: main carries content, secondary is labels/structure, weak is metadata, faint is «optional to read» hints. Distinguished by lightness, not hue.

TokenDark hexANSI 256Light hexUse

③ Accent (same source as the logo)

Cyan is the brand primary and the only «interaction focus» color: active border, title, selected row, focus all use it. Gold is the secondary accent, exclusive to the viden wordmark and work mode.

TokenDark hexANSI 256Light hexUse

④ Semantic

Five states each own a hue, never confused: success green, warning/pending gold-yellow, error/reject red, in-progress blue (deliberately split from brand cyan, meaning «the machine is running»).

TokenDark hexANSI 256Light hexUse
ANSI 256 degradation rule: When truecolor is unavailable, hue is restored before lightness. The three background tiers compress to four approximate grays (232/233/234/236), so the highlight row keeps an extra ANSI 38 cyan left bar — even if the background collapses to gray, the selector focus is not lost. Semantic colors all land on pure points of the 6×6×6 color cube (38/179/214/71/167/39) for maximum cross-terminal consistency.
Hierarchy · attention ladder

Who should be bright, who should recede

The cockpit is fundamentally about «supervision», so visual weight must follow «how much it needs your decision». From most eye-grabbing to most quiet, six regions form a five-step ladder.

1

Approval prompt

Blocking, requires an immediate decision. The only element allowed a gold-yellow solid badge + border; dims everything else when shown. Default focus lands on Approve.

warning solidscrim dims bgdiff preview
2

In progress LIVE WORK / delegated lanes

«What’s happening now». Cyan border on a light ground + in-progress blue pulse dot, resident at the transcript tail. Lane progress uses a blue bar — the only block in the right rail allowed to be «bright».

accent borderprogress pulse
3

Selector highlight row

The anchor of selector-first interaction. The highlight row uses bg-sel + cyan left bar + brightened text — the only «lit» row in any list. Its contrast must exceed all static information.

bg-sel backgroundcyan left barbrightened text
4

Transcript tail (latest content)

The conversation body. The latest line uses main text color, history gradually converges to secondary. Semantic results (failed/passed) are colored in place, but never outshine LIVE WORK.

fg-primary mainhistory → fg-secondary
5

Snapshots — workspace / diagnostics / provider health / recent files

Reference information, quiet by default. Title in cyan, key in secondary, value in main, but the whole recedes to the right rail; only on error/anomaly does the relevant row «light up one cell» in a semantic color.

title accent · body mutedlights up only on anomaly
Key state · approval popup

Approval is the cockpit’s top priority

When a permission request appears, the background dims, and a gold border + solid badge push it to the front. The diff preview is colored green/red in place; default focus is on Approve, y / Enter approves.

New mode · Lane monitor (subagent monitoring)

When subagents start running, there’s a place to watch

A dedicated LANE MONITOR mode: when a lane fans out subagents, LIVE WORK shows a 3 subagents ▸ hint; press ^L (or /lanes) to enter. Pick a lane on the left, the right shows the subagent hierarchy tree + the focused node’s live output, all on a pure character grid: tree uses box-drawing, progress bars use █░, the selector highlight is consistent throughout. Esc returns to the cockpit without interrupting the main conversation.
