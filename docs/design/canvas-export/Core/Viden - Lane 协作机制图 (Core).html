四个协作原语 · collaboration primitives
交接handoff

把产物从一条 lane 推给另一条，触发对方开新 session。单向、有明确的交付物。

L1 design-spec → L2/L3 开工
评审请求review request

A 的产出送 B 给意见或批准，带审批闸。任何 lane 都能向任何 lane 发起 —— 评审是动作不是角色。

契约contract

所有 lane 共享的单一事实来源，存放于 contracts/。只读引用，修改必须走评审闸。

依赖dependency

B 的 session 阻塞在 A 的产出上，A 的契约定稿后自动解锁。驾驶舱里表现为 lane 的 waiting 状态。

L2/L3 方案 ← 依赖 → 设计契约 v1.0
三个已选定的设计决策 · decisions
隔离 vs 共享工作区？
已选 A每条 lane 独立 worktree + 分支，天然防冲突；最后经集成闸合并，冲突退回原 lane。
评审是角色还是动作？
已选 动作任何 lane 可向任何 lane 发评审请求；也可把某条 lane 标记为常驻评审职责。
谁来编排协作？
先 手动人在驾驶舱里点交接 / 批闸；自动编排（orchestrator lane）留作 v2。
备注 · 时间自上而下；同一相位内各 lane 并行。lane 内多 session（S1/S2…）可同时活跃 —— 如 ④ 中 L1 在「设计跟进」的同时，L2/L3 各自实现。所有跨 lane 的线都至少经过一个 ⏸ 闸，lane 内部（session → subagent）则完全自治。
